## 1. 결론이 없다 — CTA 씬 부재 (치명)

`planShorts` 프롬프트는 명시적으로 요구합니다(`src/orchestrator/shorts.ts:648`):

> 씬1=훅, 씬2=전제, **마지막 씬=CTA**

그런데 실제 산출물의 마지막 씬은:

```json
{ "kind": "list", "narration": "빨리 자라면 손이 자주 가고, 느리게 자라면 덜 가요. 대개 천천히 자라는 나무가 관리하기 쉬워요.",
  "items": ["회양목: 초여름 한 번", "쥐똥나무: 두 번", "측백류: 봄·늦여름 두 번"] }
```

`kind: "list"`입니다. CTA 씬이 **아예 없습니다.**

이게 왜 치명적이냐면, 프롬프트의 **결론 의무** 조항이 정확히 이 상황을 금지하고 있기 때문입니다:

> 영상 전체에 명시적 판정 또는 행동 결론을 최소 1개 남기고, **결론을 다음 편 예고로 대체하지 마라.**

영상을 순서대로 들어보면:

1. 옆집 창이 마당을 본다 (문제 제기)
2. 두 가지를 적어라 — 높이와 손 가는 횟수 (방법)
3. 빗자루로 높이를 재라 (방법)
4. 위를 좁게 다듬어라 (다른 주제)
5. 빨리 자라면 손이 자주 간다 + 수종 3개 (정보)

**"그래서 무엇을 심어라"가 한 번도 없습니다.** 원본 블로그는 5행짜리 표로 "무릎~허리면 회양목, 키를 넘는 벽이면 향나무·측백류"라는 **자리→수종 매핑**을 주는데, 숏폼은 그 매핑의 절반(손질 횟수)만 떼어 와서 목록으로 만들었습니다. 시청자가 얻는 건 "천천히 자라는 게 관리하기 쉽다"는 일반론뿐입니다.

원본의 마지막 문단은 명확한 행동 지시로 끝납니다 — "빗자루 들고 담장 앞에 서서 그 숫자를 적고, 담장 길이를 재 두세요." 이 문장이 숏폼 CTA로 그대로 왔어야 합니다.

**놓친 게이트:** `standaloneQa.ts:37` 항목 4가 정확히 이걸 검사합니다 — "결론 부재 — 관찰·확인법만 나열하고 그것이 무엇을 뜻하는지(판정) 또는 무엇을 하라는 것인지(행동)가 끝까지 한 번도 없는가". 검사는 돌았지만(`stdModel()`이 claude 계열이라 게이트 통과) 이 건을 보고하지 않았습니다. LLM 판정의 미검출입니다.

## 2. 예고가 조용히 사라졌다 (중대)

plan.json에는 예고가 선언돼 있습니다:

```json
"next": { "topic": "울타리 나무 간격 계산과 심는 순서", "window": "9월" }
```

그런데 `data/promises/index.json`에 **이 약속이 없습니다.** 24건 중 최신은 08-01자입니다.

원인을 역추적했습니다. `promises.ts:155`:

```ts
if (this.pending(brand ?? '').length >= MAX_PENDING) return null; // 남발 가드 — 호출측이 로그
```

`MAX_PENDING = 12`이고, **bionditree pending이 정확히 12건**입니다:

| 상태 | 건수 |
|---|---|
| pending | 12 (= 상한) |
| dropped | 12 |
| **fulfilled** | **0** |

7월 29일~8월 1일 사이에 12건이 쌓인 뒤, **한 건도 이행된 적이 없습니다.** 8월 1일 이후 모든 예고가 캡에 막혀 조용히 버려지고 있었다는 뜻입니다. 이번 건은 그 27일째 사례입니다.

`shorts.ts:1128`이 `say('예고 등록 보류 — 미이행 약속이 가득(백로그 캡)')`을 남기지만, 이건 런 로그일 뿐 검토 알림에는 안 나갑니다. 사용자는 CTA에서 "다음 편에 간격 계산을 다루겠다"고 **약속한 영상을 발행하는데, 시스템은 그 약속을 지킬 계획이 없습니다.**

> 이건 이번 숏폼만의 문제가 아니라 **예고 이행 루프 자체가 8월 1일 이후 죽어 있다**는 발견입니다. 별도 조치가 필요합니다.

## 3. 씬2가 훅을 받지 않는다 (중대)

프롬프트는 씬2의 역할을 못박습니다:

> 씬2=전제(이 영상이 무엇에 대한 이야기이고 왜 문제/중요한지를 못박는다 — **원문의 핵심 인과 한 줄**)

실제:

- **씬1(훅):** "옆집 이층 창이 마당을 내려다봐요." → 사생활 침해라는 **긴장**을 세움
- **씬2:** "울타리 나무를 고르기 전엔 두 가지부터 적어요. 가려야 할 높이, 그리고 일 년에 가위를 몇 번 들 수 있는지예요."

씬2가 훅의 긴장을 **받지 않고** 곧바로 방법론으로 넘어갑니다. "옆집 창이 보인다 → **그래서 가려야 한다** → 가리려면 높이를 알아야 한다"는 인과의 가운데 고리가 없습니다.

게다가 "일 년에 가위를 몇 번 들 수 있는지"는 훅이 세운 사생활 문제와 **아무 관계가 없습니다.** 관리 난도는 원본에서 두 번째 축인데, 훅이 첫 번째 축(차폐)만 세워 놓고 씬2가 두 축을 한꺼번에 던지니 시청자는 "왜 갑자기 가위 얘기지?"가 됩니다.

원본 블로그는 이 연결을 제대로 합니다 — "담장은 그대로인데 옆집 2층 창이 마당 한가운데를 내려다봅니다. **그럼 나무를 몇 미터짜리로 심어야 할까요.**" 이 한 문장이 숏폼에서 누락됐습니다.

**놓친 게이트:** `standaloneQa.ts:36` 항목 3(전제 도약)의 소관입니다.

## 4. 원문의 미검증 사실이 숏폼에 `pass`로 실렸다 (중대 — 구조적)

이게 가장 조용하고 위험한 결함입니다.

**원본 블로그** `fact_gate.json`:
```
status: hold
unsupported 1건: "늦여름 이후에는 질소 성분이 많은 거름을 줄입니다."
unverified 6건: 회양목/사철나무/꼬리조팝나무/향나무·측백류 손질 시기, 붉은별무늬병 증상 …
```

**숏폼** plan.json:
```json
"factGate": { "status": "pass", "unsupported": [], "contradicted": [] }
```

그런데 숏폼 씬5의 `items`는 이렇습니다:

```
회양목: 초여름 한 번   ← 원본에서 unverified
쥐똥나무: 두 번        ← 원본에서 unverified
측백류: 봄·늦여름 두 번 ← 원본에서 unverified
```

**원본에서 "근거 미확인"으로 분류된 바로 그 수치들이, 숏폼에서는 검증된 사실인 양 `pass` 딱지를 달고 화면 목록으로 나갑니다.**

코드에서 확인한 구조적 원인 — 파생 게이트는 두 가지만 봅니다:

1. `parityIssues()` — 대본이 **원문 본문과 어긋나는가**
2. `timingParityIssues()` — 원문에 없는 시기·수치를 지어냈는가

씬5의 items는 원문 표에 **그대로 있으므로** 두 검사 다 통과합니다. `parityToInfo()`(`standaloneQa.ts:76-78`)는 정합 지적이 없으면 무조건 `status: 'pass'`를 냅니다. **원본 piece의 `factGate.unverified`를 파생물이 승계하는 경로가 코드에 존재하지 않습니다** (`grep unverified src/orchestrator/shorts.ts` → 0건).

즉 파이프라인은 "원문에 충실한가"만 묻고 "**원문이 애초에 믿을 만한가**"는 묻지 않습니다. 블로그는 사람이 검토 알림에서 `⚠ 사실 게이트 보류`를 보고 거르지만, 파생 숏폼은 깨끗한 얼굴로 나갑니다. facts-only 절대 규칙(08-26) 관점에서 이건 메워야 할 공백입니다.

숏폼이 블로그보다 먼저 발행될 수도 있다는 점에서 더 그렇습니다.

## 5. 32.1초 — 목표 초과 (경미)

- `SHORTS_MAX_DURATION_SEC=40` → 낭독 목표 **20~30초**, 글자 예산 206자
- 실측: 내레이션 **201자** (예산 내 ✅) / TTS 합계 **29.2초** / 영상 **32.1초**

씬별 TTS: 2.6 · 9.1 · 5.7 · 3.4 · 8.3초

글자 예산(201/206자)은 지켰는데 시간이 넘쳤습니다. 숫자를 맞춰 보면:

| 항목 | 값 |
|---|---|
| 코드 상수 `SHORTS_TTS_CPS` | 5.9자/초 |
| 실측 낭독 속도 | 201자 ÷ 29.2초 = **6.88자/초** |
| 나레이션 합계 | 29.2초 |
| 최종 영상 | 32.1초 (+2.9초 = 씬 전환·여백) |

실측 속도가 상수보다 **빨랐는데도**(6.88 > 5.9) 30초를 넘겼습니다. 즉 글자 예산은 오히려 보수적이었고, 초과분은 전적으로 **렌더 오버헤드 2.9초**에서 나옵니다. 예산 공식 `(capSec - 5) × 5.9`의 "5초 여유"가 TTS 속도 편차와 업로드 인트로(1.6초)만 상정하고 씬 전환 여백은 안 봅니다.

40초 하드캡은 안 넘겼으니 발행은 되고, 이 건은 메시지 전달과 직접 관계가 없습니다. 다만 목표 상단(30초)을 넘긴 사실은 기록해 둡니다.

## 무엇을 고칠 것인가

우선순위 순입니다.

### A. 예고 백로그 사망 (즉시)
pending 12/12·fulfilled 0 — 8월 1일 이후 모든 예고가 소실됐습니다. 27일치 약속이 버려졌습니다.
→ ① 만석 pending을 검토해 이행/폐기 정리 ② 캡 도달 시 검토 알림에 경고 줄 추가(로그만으론 아무도 모름) ③ 이행 루프가 왜 한 건도 안 돌았는지 별도 추적.

### B. CTA 씬 결정적 린트 (높음)
프롬프트가 "마지막 씬=CTA"를 요구하는데 LLM이 안 지켰고 아무도 안 잡았습니다. 문체 린트·훅 린트와 같은 사상 — **결정적 검사**로 `plan.scenes[last].kind !== 'cta'`를 잡아 수정 라운드에 얹으면 프롬프트-only 누출을 막습니다. 전례가 이미 있습니다(`hookKeywordLeadIssues` — "프롬프트 지시 단독은 샌다는 실측").

### C. 원문 factGate 승계 (높음)
파생물 생성 시 원본 piece의 `factGate.unverified`/`unsupported` 문장이 대본·카드 카피에 **재등장하는지** 대조해, 재등장하면 파생 factGate에 승계. 원문이 "모르는 것"은 파생물도 모르는 것이어야 합니다.

### D. 씬2 전제 연결 (중간)
`standaloneIssues` 항목 3이 놓쳤습니다. 프롬프트에 "씬2는 훅이 세운 긴장을 받아 그 인과를 잇는다"를 명시적으로 추가하는 쪽이 검사 강화보다 쌉니다.

### E. 시간 예산 여유 (낮음)
`budgetChars` 공식에 렌더 오버헤드 ~2초를 반영. 40초 캡 안이라 시급하지 않습니다.

## 참고 — 잘 된 부분

공정하게 적어 둡니다. 훅("옆집 이층 창이 마당을 내려다봐요")은 키워드 낭독으로 열지 않았고, 구체적 장면으로 시작해 첫 2초 규칙을 지켰습니다. 배경 이미지 5장의 스타일 일관성도 유지됐고(공통 스타일 프리픽스), 씬3의 "빗자루로 높이 재기"는 원본의 가장 실용적인 대목을 정확히 골라냈습니다. 캡션의 향나무·사과배 경고도 원문 핵심을 살렸습니다.

문제는 **재료가 아니라 배열**입니다. 좋은 조각들이 결론 없이 끝나서 메시지가 서지 않았습니다.
