# 키워드 클러스터 백로그 — 설계

2026-08-06 · 상태: 사용자 검토 대기

## 목표

주제 1개를 넣으면 연관 검색어(자동완성)가 여러 개 나온다 — 지금은 이 목록이 그라운딩 텍스트로 뭉개져 한 편에만 쓰이고 버려진다. 이를 **대표 1편 + 형제 검색어 백로그**로 바꿔, 오토런이 간격을 두고 형제들을 서로 다른 이야기로 소진하게 한다. 한 주제 입력 = 여러 편의 씨앗.

예(실측 2026-08-03, "추희자두"): 수확시기 / 묘목 / 후무사 차이 / 후숙 / 병충해 … 10개 중 대표 1편만 쓰이고 9개는 증발했다.

## 사용자 확정 결정 (2026-08-03 + 08-06)

1. **산출 형태**: 대표 1편 즉시 + 나머지는 백로그(한꺼번에 N편 생성 금지 — 도배 방지).
2. **소진 주체**: 오토런이 알아서, 간격을 두고. 수동 지명 UI는 이번 범위 밖.
3. **채굴 시점**(08-03 미결 → 기본값 가정으로 진행): 수동 입력 주제 + 오토런 아이디어 둘 다. 지식 리서치 런은 제외(draft 없는 조사 런이라 클러스터 소유 주제가 없음).

## 전제 — 이미 해결된 것

- **형제 글들이 서로 다른 내용이 되는 장치**: priorCoverage 재대조(9e52e4f, 08-06 수선). 형제는 정의상 같은 키워드 계열이라 이 가드가 반드시 발화하며, 앞선 편의 구성을 주입해 프레이밍을 강제로 바꾼다. 08-03 설계 당시엔 이 가드가 무발화 상태였다 — 지금은 실 LLM 재생으로 검증됨.
- **실코퍼스 검증(08-03, 41건)**: 형제 후보 5종 전부 ①포화 게이트(saturatedThemeMatches) 통과 ②신규성 게이트(findSimilarContent)는 시드 글과의 키워드 포함 때문에 전부 차단. → 신규성 게이트에 "계획된 갈래" 예외가 필요하고, 포화 게이트는 손댈 필요 없다.

## 설계

### ① 채굴 — 주제 확정 직후 1회

- `naverAutocomplete(seed)` **배열 그대로** 사용(현재 `naver_autocomplete.ts:36`이 텍스트로 뭉개는 것과 별개 경로 — 그라운딩 커넥터는 불변).
- micro 1회로 각 검색어 판정: `{ keyword, title(가제), angle(검색 의도), verdict }`.
  - 기각 사유: 브랜드 범위 밖(`offBrandTerm`) / 시드와 동의어(각도 차이 없음) / **시드 제외 후에도** 기존 콘텐츠와 novelty 충돌(진짜 중복 — 실측: "추희자두 묘목"은 이미 발행된 글이 있었다).
- 트리거 지점: **`advancePieceReady`(대표 편 초안 확정) 단일 훅** — 수동·자율 런이 여기서 합류하므로 한 곳으로 두 경로를 다 덮고, `seedPieceId`가 항상 확보되며, 중도 실패한 런에 대한 낭비 채굴이 없다. 리비전 승격(revised)은 제외(같은 글 재확정이지 새 주제가 아님). fire-and-forget·전량 fail-open — 채굴 실패가 ready 승격을 막지 않는다.

### ② 저장 — 새 스토어 `data/topics/backlog-<brand>.json`

예고 대장(promises) 재사용 금지. 근거:
- `MAX_PENDING=12`가 브랜드 공유 캡 — 클러스터 6건이 시청자 약속 슬롯을 잠식하고, 초과 시 `create()`가 null을 반환해 파생 콘텐츠의 "다음 편" 예고가 조용히 유실된다.
- `dueMonth` 없는 항목은 `isDue`가 영구 false — 형제 검색어엔 자연스러운 달(月)이 없어 쌓이기만 하고 안 나온다.
- 의미가 다르다: 예고는 갚아야 할 빚(시즌 창·신뢰), 클러스터는 재고(기회·무기한).

스토어 형태는 promises 패턴 복사(원자적 tmp+rename, 브랜드 격리, 입구 `offBrandTerm` 게이트):

```ts
interface ClusterTopic {
  id: string; brand?: string;
  seedKeyword: string;      // 클러스터 시드("추희자두")
  seedPieceId?: string;     // 대표 1편 piece
  keyword: string;          // 형제 검색어("추희자두 후숙")
  title: string;            // 가제(소진 시 재검증)
  angle?: string;           // 검색 의도 한 줄
  status: 'pending' | 'consumed' | 'dropped';
  consumedPieceId?: string;
  createdTs: string; updatedTs: string;
}
```

- 클러스터당 저장 상한: 시드당 형제 최대 6건(채굴 판정 통과분 중 상위).
- 브랜드 캡: pending 총량 24건(초과 채굴은 버림 — 로그만).

### ③ 소진 — `pickAutoWork` 우선순위 한 칸

재개 → 리서치 → 예고 이행 → **클러스터** → 신규 아이디어 → 파생.

- 예고보다 뒤(약속 먼저), 신규 아이디어보다 앞(검색 수요가 자동완성으로 이미 검증된 주제라서).
- 소진 시점 재검증: `offBrandTerm` + novelty(시드 piece 제외) + 포화 게이트 — 채굴 시점과 소진 시점 사이에 코퍼스가 변했을 수 있다. 걸리면 `dropped`(사유 로그), 다음 항목 시도.
- 케이던스 불변: 기존 `canGenerateNew`(주 N편) 안에서 슬롯만 차지 — **생산량은 늘지 않고 다양성만 늘린다.**

### ④ 도배 방지

- 같은 시드의 형제가 **최근 자율 blog 3편 안에 있으면** 클러스터 칸 건너뜀(신규 아이디어로 폴백) — "추희자두 주간" 방지.
- 클러스터당 소진 상한 4편(시드 포함 5편) — 나머지는 pending으로 남고, 코퍼스 포화 게이트가 자연 차단하면 dropped.
- `Piece`에 `clusterSeedId?: string` 필드 추가(간격 판정·성과 귀속용).

### ⑤ 서로 다른 이야기 보장

- 형제 piece는 **자기 keyword를 갖고 런에 전달**(`launchRun(title, { keyword })`) — SEO 과녁 고정 + priorCoverage 유사도 판정의 입력. 예고 이행 경로(`main.ts:3311`)가 keyword를 빠뜨리는 기존 실수를 반복하지 않는다.
- priorCoverage가 시드 편과 앞선 형제들의 구성을 주입(수선 완료 전제) — 신규성 게이트는 `clusterSeedId` 있는 piece 생성 경로에서만 "시드·형제 제외 후 재검사"로 완화.

### 킬스위치·격리

- `TOPIC_CLUSTER=off` — 채굴·소진 모두 정지(스토어는 보존).
- 브랜드 격리: 스토어 파일·조회 전부 brand 슬러그 정확 일치(기존 원칙).

## 범위 밖 (이번에 안 함)

- 웹 UI 목록/지명 실행(추후 성과 탭에 읽기 전용 노출 검토).
- 리서치 런 산출물에서의 채굴.
- 검색광고 API 검색량 기반 우선순위(초기엔 자동완성 순서 = 인기 근사로 충분).
